# Analyse exhaustive RainLoop 1.17 : static/js/app.js lignes 8000 à 16000

Fichier lu : `/Work/webmail_project/rainloop/1.17.0/static/js/app.js` (bundle webpack, lecture directe des lignes 8000-16000).
Contenu de la tranche, module par module (les modules `node_modules/*` : core-js, babel runtime, addressparser, etc. sont des libs embarquées, ignorées ; seuls les modules `./dev/*` sont du code RainLoop).

Modules première partie lus intégralement : AppUserStore (fin, 7990-8062), Component/Abstract (8148), Stores/User/Settings (8350), Common/Plugins (8451), Stores/User/Pgp (8652, survolé : 100 % OpenPGP), Stores/User/Account (9130), Storage/Client (9527), Common/Momentor (9573), Helper/Message (9770), Knoin/AbstractModel (9982), Stores/Language (10117), Model/Email (10357), Common/Audio (10627), Component/AbstractInput (10845), Promises/User/Ajax (11035), Stores/User/Identity (11237), Stores/User/Contact (11272), Common/Jassl (11720), Stores/Theme (11798), Stores/User/Notification (11840), **View/Popup/Compose (12241-14031, cœur de la tranche)**, Knoin/AbstractScreen (14628), Storage/RainLoop (15109), Component/AbstractCheckbox (15623). Les lignes 15696-16000 sont `emailjs-addressparser` (lib embarquée).

Ce que je n'ai PAS pu lire : rien dans la tranche. Limite : les dépendances appelées depuis ces modules (Model/ComposeAttachment, HtmlEditor, Knoin, Cache, Jua, Popups Ask/Contacts/FolderSystem) sont hors tranche : je décris leur effet visible tel que l'appelant le suppose, sans les avoir lues ici. La comparaison avec wmail-go a été faite sur compose.go, compose.js, editor.js, chips.js, contacts-ac.js, keys.js, poll.js, notify-setting.js, mail.go (formatDate/listDate), settings.html, userdata.Settings, compose.html, mail.css (grep ciblé pour les cases à cocher).

Contexte d'architecture à garder en tête : RainLoop compose dans une **fenêtre modale (popup) réductible** au-dessus de la boîte (état `composeInEdit`), wmail-go compose dans une **page dédiée** (`HideNav`, sans JS obligatoire, `compose.html` + `compose.js`). Beaucoup de comportements « popup » n'ont donc pas d'équivalent direct.

Légende verdicts : OK, PARTIEL, MANQUANT, SANS OBJET. Priorités : P1 quotidien et très visible, P2, P3.
