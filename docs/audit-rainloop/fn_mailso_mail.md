# Analyse RainLoop 1.17 — MailSo/Mail et MailSo/Cache contre wmail-go

Périmètre : `app/libraries/MailSo/Mail/*.php` (MailClient, Message, MessageCollection, Folder, FolderCollection, Attachment, AttachmentCollection, 3 classes d'exceptions sans méthode) et `MailSo/Cache/*` (CacheClient, DriverInterface, 4 pilotes). Toutes les fonctions ont été lues. 207 fonctions analysées.

Légende : OK / PARTIEL / MANQUANT / SANS OBJET. Les références `fichier:ligne` du Go sont relatives à `/home/gdegoulet/Work/webmail_project/internal/`. Les pièces jointes, l'affichage et les actions de liste sont dans `web/mail.go`, la couche IMAP dans `mailconn/`.

Constats transverses importants (détaillés dans les lignes et repris dans « À ajouter ») :
- Liste non rafraîchie automatiquement quand un nouveau message arrive (RainLoop met la liste à jour quand `UidNext` change) : `web/static/poll.js` ne met à jour que le badge, le titre et les notifications.
- RainLoop masque par défaut les messages `\Deleted` (`MessageListUndeletedOnly = true`) : wmail-go ne filtre pas.
- Message affiché = téléchargement complet du message (plafond 30 Mo, pièces 25 Mo) au lieu d'un FETCH par partie en flux.
- Format `text/plain; format=flowed` non décodé.
- Marquer lu/non lu une conversation ne touche que le message représentant.
